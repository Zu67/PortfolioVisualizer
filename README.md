# PortfolioVisualizer

This branch is `DevelopmentPortfolioVisualizer`. The commits that added the scripts run from 2024-04-30 ("Initial commit") through 2024-05-13 ("Updating PortfolioVisualizer"). Later commits moved those files into `scripts/` and updated this README.

| File | What it does |
| --- | --- |
| `scripts/Data Generator.py` | Uses Faker to write 100 rows to a local `transactiondata.csv`, with no index column. The columns are `date`, `stock_symbol`, `transaction_type`, `broker`, `quantity`, and `price`. The symbol is four letters. The type is `buy` or `sell`. The broker is a fake person's name. Quantity is an integer from 1 to 100. Price is `random.uniform(10.0, 500.0)` rounded to 2 decimal places. |
| `scripts/PortfolioData` | Reads a local `PortfolioData.csv`, uses the `Date` column as the index, and plots `pct_change().cumsum()`. That is the running sum of daily percent changes, not a compounded return. The chart title is "Portfolio Performance". The y-axis label is "Cumulative Returns". The legend is in the upper left. |
| `scripts/PortfolioVisualizerInGit.py` | Prints two downloads of the last 300 calendar days of VTI and SPY, then stops. A third copy of that download is not reached. See below. |

`scripts/PortfolioVisualizerInGit.py` prints two downloads of VTI and SPY. Each window is `datetime.now()` minus 300 days through `datetime.now()`. The same block is pasted a third time after the `df` loop, and that copy does not run. The next loop reads `df`, which this file has not assigned, so running it from the top stops there. The lines after that are not reached. The loop calls `df.items()` and unpacks each key as `(universe_symbol, time)`, so `df` has to be a mapping of those pairs, not a table. `constituents_df` is the table built from that mapping. The next filter walks that table as if each item had `HasFundamentalData`. Iterating a DataFrame yields column names, so `fundamental` is a string and `fundamental.HasFundamentalData` raises `AttributeError` even after `df` was assigned. The lines after that build Morningstar-style super-sector, sector, and industry lookup tables. The industry table spells one row "Lumber & Wood Prodcution". The Furnishings group is "Furnishings, Fixtures, & Appliance", and its industry row is "Furnishings, Fixtures, & Appliances". The Forest Products group also has industry code `10130020` labeled "Specialty Chemicals", the same code and name as the Chemicals row. The pie charts select `2024-03-26` and the titles say `2023-03-26`. The sector line chart is titled "Sector Weights Over Time" and the super-sector line chart is titled "Super Sector Weights Over Time". Both legends are titled "Industry". The last cells use `df_security`, `df_benchmark`, `selected_symbol`, and `selected_benchmark`, which are also not defined here. The daily risk-free rate is `(1.05) ** (1/252) - 1`. Beta is one number for the whole series, the covariance of the two raw return series divided by the variance of the benchmark. The first percent-change row is missing and is left out of that covariance. Sharpe is that day's excess return divided by the 30-day rolling standard deviation of excess returns. The rolling window needs 30 numbers, so the first 30 rows have no Sharpe, Treynor, or Jensen value. A 30-day standard deviation of 0 makes that day's Sharpe infinity when the excess return is not 0, and NaN when it is 0. Treynor is the 30-day mean of excess return, times 252, divided by beta. Jensen's alpha is the 30-day mean of return minus the expected daily return, times 252. The chart title is "Rolling Investment Metrics" even though the Sharpe numerator is one day. The last chart title is "Price Comparison", and the series is cumulative percent return, labeled with `selected_symbol.Value` and `selected_benchmark.Value`.

The default branch, `main`, also has the holding-cost scripts and `data/ETF Constituent Data - Examples.csv`.
