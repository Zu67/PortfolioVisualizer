# PortfolioVisualizer

Python scripts for positions built from a brokerage export and for prices from Yahoo Finance. The exports themselves are not in this repository. `.vscode/settings.json` sets only `files.autoSave` to `afterDelay`. `.gitattributes` is the one line `* text=auto`, under the comment "Auto detect text files and perform LF normalization".

| Script | What it does |
| --- | --- |
| `scripts/Data Generator.py` | Uses Faker to write 100 rows to `transactiondata.csv` in the current directory, with no index column. `Faker()` and `random` are not seeded, so each run writes a different file. The columns are `date`, `stock_symbol`, `transaction_type`, `broker`, `quantity`, and `price`. `fake.date()` is called with no arguments. In Faker 40.1.0 that call formats the date as `YYYY-MM-DD` and draws the instant from 1970-01-01 00:00:00 through the current time, then drops the time. The symbol is four letters drawn from `A` through `Z`, and the same symbol can appear more than once. The type is `buy` or `sell`. The broker is a fake person's name. Quantity is an integer from 1 to 100. Price is `random.uniform(10.0, 500.0)` rounded to 2 decimal places. |
| `scripts/portfolio_calculation_quinn.py` | Reads `robinhood_data.csv` and skips a malformed line. A dollar sign or comma is removed, and an amount in parentheses is read as negative. Holding cost is that amount times -1, so a positive amount becomes a negative cost and flips the quantity's sign. The comment says the sort is by instrument and activity date. The code sorts only by activity date. Average price is the running cost divided by the running quantity. Dividing by a running quantity of 0 yields infinity when the running cost is positive, negative infinity when that cost is negative, and NaN when that cost is also 0. On pandas 3.1.1, rounding those three values leaves them unchanged. Rows that share an activity date are not ordered by instrument, and the sort does not ask for a stable order, so their order can change and the running cost follows it. Aggregated quantity and average price are then rounded to 2 decimal places. The running cost itself is not rounded. Rows with a missing field are dropped after that sign flip. It does not expand the calendar. `math` is imported and unused. The download passes the last activity date as `end`. yfinance treats `end` as exclusive, so that date is not requested. In yfinance 1.8.0, `download` defaults to `auto_adjust=True` and `multi_level_index=True`. The price columns are Close, High, Low, Open, and Volume. There is no `Adj Close`, so `data['Adj Close']` raises `KeyError: 'Adj Close'`. The stack, the rename, and the merge are not reached. Gain/Loss is market value minus that unrounded running cost, not minus the rounded average price times quantity. It prints only the ITOT rows, and those columns include Quantity. |
| `scripts/robinhood_portfolio_manipulation.py` | Reads the same file and skips a malformed line. A dollar sign or comma is removed, and an amount in parentheses is read as negative, before any row with a missing field is dropped. It does not keep only buys and sells. It expands every calendar day from the first remaining date through the last, for every remaining symbol, and only then sets holding cost to the amount times -1. Quantity flips sign when that cost is negative. Aggregated quantity and average price are rounded to 2 decimal places. It then calls `fillna(method='ffill')` on the groupby of quantity, aggregated quantity, and average price. On pandas 3.1.1 that groupby result has no `fillna`, so the line raises `AttributeError: 'DataFrameGroupBy' object has no attribute 'fillna'` and nothing is filled forward. `math` is imported and unused. The download passes the last activity date as `end`, and yfinance treats that `end` as exclusive, so that date is not requested. On pandas 3.1.1 the groupby `fillna` line raises first, so this download is not reached. In yfinance 1.8.0 the call defaults to `auto_adjust=True` and `multi_level_index=True`, and the columns are Close, High, Low, Open, and Volume. There is no `Adj Close`, so `data['Adj Close']` raises `KeyError: 'Adj Close'` before the stack, the rename, or the join. The running holding-cost sum is discarded before the download. Dividing by a running quantity of 0 yields infinity when the running cost is positive, negative infinity when that cost is negative, and NaN when that cost is also 0. On pandas 3.1.1, rounding those three values leaves them unchanged. Total Cost is computed again as aggregated quantity times that rounded average price, so a flat position makes Total Cost and Gain/Loss NaN. Gain/Loss is market value minus that product. That product is not one of the printed columns. The printed columns are activity date, instrument, aggregated quantity, average price, adjusted close, market value, and gain/loss. It prints the last 25 rows. |
| `scripts/schwab_portfolio_manipulation.py` | Reads `Roth_IRA.csv` and does not skip a malformed line. An unparseable date is dropped. Dollar signs and commas are removed. Parentheses are not turned into a minus sign, so an amount such as `($1.00)` raises `ValueError` and the script stops. The calendar and the symbol list are built from every remaining dated row, including rows that are not a buy or a sell. It then keeps only Buy and Sell. Holding cost is the amount times -1, and a negative cost flips the quantity's sign. Aggregated quantity and average price are rounded to 2 decimal places. Dividing by a running quantity of 0 yields infinity when the running cost is positive, negative infinity when that cost is negative, and NaN when that cost is also 0. On pandas 3.1.1, rounding those three values leaves them unchanged, and the printed average price keeps that result. It calls `fillna(method='ffill')` on the groupby of quantity, aggregated quantity, and average price. On pandas 3.1.1 that groupby result has no `fillna`, so the line raises `AttributeError: 'DataFrameGroupBy' object has no attribute 'fillna'` and nothing is filled forward. It imports `yfinance` and does not call it. `print(df.tail())` prints the last 5 rows and every column, including Action, Price, Amount, Holding Cost, and Total Cost. |
| `scripts/PortfolioVisualizerInGit.py` | Prints two downloads of the last 300 calendar days of VTI and SPY, then stops. A third copy of that download is not reached. See below. |
| `scripts/PortfolioData` | Reads `PortfolioData.csv` from the current directory. That file is not in this repository, so running the script here raises `FileNotFoundError` before a plot. It uses the `Date` column as the index and plots `pct_change().cumsum()` with no arguments. The first percent change is missing. That is the running sum of daily percent changes, not a compounded return. The chart title is "Portfolio Performance". The y-axis label is "Cumulative Returns". The legend is in the upper left. |
| `scripts/plaid_quickstart.py` | Shell notes for the public Plaid quickstart, saved with a `.py` name. The first bare line is `git clone https://github.com/plaid/quickstart.git`, so running the file with Python stops there. It tells you to copy `.env.example` to `.env` and fill in `PLAID_CLIENT_ID` and `PLAID_SECRET`. It does not contain those values. |

`scripts/PortfolioVisualizerInGit.py` prints two downloads of VTI and SPY. Each window is `datetime.now()` minus 300 days through `datetime.now()`. In yfinance 1.8.0 those calls default to `auto_adjust=True` and `multi_level_index=True`. The printed header has two rows, `Price` and `Ticker`, and the columns are Close, High, Low, Open, and Volume. There is no `Adj Close`. The start calendar date is included when that day has a bar, even if the time is later that day. yfinance treats `end` as exclusive, so the calendar date of `datetime.now()` is not in the frame. The same block is pasted a third time after the `df` loop, and that copy does not run. The next loop reads `df`, which this file has not assigned, so running it from the top stops there. The lines after that are not reached. The loop calls `df.items()` and unpacks each key as `(universe_symbol, time)`, so `df` has to be a mapping of those pairs, not a table. `constituents_df` is the table built from that mapping. The next filter walks that table as if each item had `HasFundamentalData`. Iterating a DataFrame yields column names, so `fundamental` is a string and `fundamental.HasFundamentalData` raises `AttributeError` even after `df` was assigned. The lines after that build Morningstar-style super-sector, sector, and industry lookup tables. The super-sector table has 3 rows, the sector table has 11, and the industry table has 145 rows in 55 groups. Every sector code has at least one industry row. The only repeated industry code is `10130020`. The industry table spells one row "Lumber & Wood Prodcution". The Furnishings group is "Furnishings, Fixtures, & Appliance", and its industry row is "Furnishings, Fixtures, & Appliances". The Forest Products group also has industry code `10130020` labeled "Specialty Chemicals", the same code and name as the Chemicals row. The pie charts select `2024-03-26` and the titles say `2023-03-26`. The sector line chart is titled "Sector Weights Over Time" and the super-sector line chart is titled "Super Sector Weights Over Time". Both legends are titled "Industry". The last cells use `df_security`, `df_benchmark`, `selected_symbol`, and `selected_benchmark`, which are also not defined here. The daily risk-free rate is `(1.05) ** (1/252) - 1`. Beta is one number for the whole series, the covariance of the two raw return series divided by the variance of the benchmark. Neither `.cov` nor `.var` passes `ddof`. On pandas 3.1.1 both default to 1. A benchmark variance of 0 makes beta NaN. A beta of 0 makes that day's Treynor infinity when the 30-day mean excess return is positive, negative infinity when that mean is negative, and NaN when that mean is 0. The first percent-change row is missing and is left out of that covariance. Sharpe is that day's excess return divided by the 30-day rolling standard deviation of excess returns. On pandas 3.1.1 that rolling deviation uses `ddof` 1, so a full window divides by 29. The rolling window needs 30 numbers, so the first 30 rows have no Sharpe, Treynor, or Jensen value. A 30-day standard deviation of 0 makes that day's Sharpe infinity when the excess return is positive, negative infinity when it is negative, and NaN when it is 0. Treynor is the 30-day mean of excess return, times 252, divided by beta. Jensen's alpha is the 30-day mean of return minus the expected daily return, times 252. The chart title is "Rolling Investment Metrics" even though the Sharpe numerator is one day. The last chart title is "Price Comparison", and the series is cumulative percent return, labeled with `selected_symbol.Value` and `selected_benchmark.Value`.
