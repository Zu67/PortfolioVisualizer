# PortfolioVisualizer

Python scripts for positions built from a brokerage export and for prices from Yahoo Finance. The exports themselves are not in this repository.

| Script | What it does |
| --- | --- |
| `scripts/Data Generator.py` | Uses Faker to write 100 rows to a local `transactiondata.csv`, with no index column. The columns are `date`, `stock_symbol`, `transaction_type`, `broker`, `quantity`, and `price`. The symbol is four letters. The type is `buy` or `sell`. The broker is a fake person's name. Quantity is an integer from 1 to 100. Price is `random.uniform(10.0, 500.0)` rounded to 2 decimal places. |
| `scripts/portfolio_calculation_quinn.py` | Reads `robinhood_data.csv` and skips a malformed line. A dollar sign or comma is removed, and an amount in parentheses is read as negative. Holding cost is that amount times -1, so a positive amount becomes a negative cost and flips the quantity's sign. The comment says the sort is by instrument and activity date. The code sorts only by activity date. Average price is the running cost divided by the running quantity. Aggregated quantity and average price are then rounded to 2 decimal places. The running cost itself is not rounded. Rows with a missing field are dropped after that sign flip. It does not expand the calendar. `math` is imported and unused. The download passes the last activity date as `end`. yfinance treats `end` as exclusive, so that date is not requested. The merge is the default inner join, so a trade with no close that day is dropped. Gain/Loss is market value minus that unrounded running cost, not minus the rounded average price times quantity. It prints only the ITOT rows, and those columns include Quantity. |
| `scripts/robinhood_portfolio_manipulation.py` | Reads the same file and skips a malformed line. A dollar sign or comma is removed, and an amount in parentheses is read as negative, before any row with a missing field is dropped. It does not keep only buys and sells. It expands every calendar day from the first remaining date through the last, for every remaining symbol, and only then sets holding cost to the amount times -1. Quantity flips sign when that cost is negative. Aggregated quantity and average price are rounded to 2 decimal places. It then forward-fills quantity, aggregated quantity, and average price. `math` is imported and unused. The download passes the last activity date as `end`, and yfinance treats that `end` as exclusive, so that date is not requested. The price join is an inner join, so a day with no adjusted close is dropped. The running holding-cost sum is discarded before the download. Total Cost is computed again as aggregated quantity times the rounded average price, and Gain/Loss is market value minus that product. That product is not one of the printed columns. The printed columns are activity date, instrument, aggregated quantity, average price, adjusted close, market value, and gain/loss. It prints the last 25 rows. |
| `scripts/schwab_portfolio_manipulation.py` | Reads `Roth_IRA.csv` and does not skip a malformed line. An unparseable date is dropped. Dollar signs and commas are removed. Parentheses are not turned into a minus sign, so an amount such as `($1.00)` raises `ValueError` and the script stops. The calendar and the symbol list are built from every remaining dated row, including rows that are not a buy or a sell. It then keeps only Buy and Sell. Holding cost is the amount times -1, and a negative cost flips the quantity's sign. Aggregated quantity and average price are rounded to 2 decimal places. It forward-fills quantity, aggregated quantity, and average price. It imports `yfinance` and does not call it. `print(df.tail())` prints the last 5 rows and every column, including Action, Price, Amount, Holding Cost, and Total Cost. |
| `scripts/PortfolioVisualizerInGit.py` | Prints two downloads of the last 300 calendar days of VTI and SPY, then stops. A third copy of that download is not reached. See below. |
| `scripts/PortfolioData` | Reads a local `PortfolioData.csv`, uses the `Date` column as the index, and plots `pct_change().cumsum()`. That is the running sum of daily percent changes, not a compounded return. The chart title is "Portfolio Performance". The y-axis label is "Cumulative Returns". The legend is in the upper left. |
| `scripts/plaid_quickstart.py` | Shell notes for the public Plaid quickstart, saved with a `.py` name. The first bare line is `git clone https://github.com/plaid/quickstart.git`, so running the file with Python stops there. It tells you to copy `.env.example` to `.env` and fill in `PLAID_CLIENT_ID` and `PLAID_SECRET`. It does not contain those values. |

`scripts/PortfolioVisualizerInGit.py` prints two downloads of VTI and SPY. Each window is `datetime.now()` minus 300 days through `datetime.now()`. The same block is pasted a third time after the `df` loop, and that copy does not run. The next loop reads `df`, which this file has not assigned, so running it from the top stops there. The lines after that are not reached. The loop calls `df.items()` and unpacks each key as `(universe_symbol, time)`, so `df` has to be a mapping of those pairs, not a table. `constituents_df` is the table built from that mapping. The next filter walks that table as if each item had `HasFundamentalData`. Iterating a DataFrame yields column names, so `fundamental` is a string and `fundamental.HasFundamentalData` raises `AttributeError` even after `df` was assigned. The lines after that build Morningstar-style super-sector, sector, and industry lookup tables. The industry table spells one row "Lumber & Wood Prodcution". The Forest Products group also has industry code `10130020` labeled "Specialty Chemicals", the same code and name as the Chemicals row. The pie charts select `2024-03-26` and the titles say `2023-03-26`. The sector line chart is titled "Sector Weights Over Time" and the super-sector line chart is titled "Super Sector Weights Over Time". Both legends are titled "Industry". The last cells use `df_security`, `df_benchmark`, `selected_symbol`, and `selected_benchmark`, which are also not defined here. The daily risk-free rate is `(1.05) ** (1/252) - 1`. Beta is the covariance of the two raw return series divided by the variance of the benchmark. Sharpe is that day's excess return divided by the 30-day rolling standard deviation of excess returns. Treynor is the 30-day mean of excess return, times 252, divided by beta. Jensen's alpha is the 30-day mean of return minus the expected daily return, times 252. The chart title is "Rolling Investment Metrics" even though the Sharpe numerator is one day. The last chart title is "Price Comparison", and the series is cumulative percent return, labeled with `selected_symbol.Value` and `selected_benchmark.Value`.

`data/ETF Constituent Data - Examples.csv` has 59,175 rows and 17 columns. The file dates are 2021-11-01 through 2021-11-05, and each of those five dates has 11,835 rows. The same constituents are repeated on each date: VXUS has 7,736 rows a day (38,680 in total), VTI has 3,997 (19,985), and QQQ has 102 (510). Every VXUS and VTI row is as of 2021-09-30, which is 58,665 rows. Each QQQ row is as of the same day as its file date.
